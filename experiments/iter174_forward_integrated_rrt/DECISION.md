# Keep the all-four gate; test allocation within the same total budget

Forward proposals now produce one independently admitted integrated completion,
chicane_left at 8 seconds with both checkpoints. The other three cases miss.
The all-four qualification is contradicted; source comparison remains closed.
Preserve the earlier 0/4 shooting result and this 1/4 result separately. Neither
establishes source recovery or a general improvement probability.

The remaining bottleneck is enough useful tree expansion before the fixed outer
transition budget ends. Bends stop before checkpoint one; chicane_right crosses
checkpoint one but not checkpoint two. All three exhaust their work allocation
well before the time cap. Local proposal qualification alone has not solved this.

A post-outcome work audit gives a concrete tradeoff. Thirty-one of 42 selected
edges occur within 128 transitions, yet each ordinary connection receives up to
1,024. Requests with no edge consume 24,297 transitions. Conversely, eleven
selected edges need later proposals; two lie on the completed path. Therefore
shorter allocation might buy useful parent/target opportunities or destroy the
one successful branch. Retrospective work after selection cannot be reclaimed
by an oracle-free controller without testing that tradeoff.

Recommended next milestone: prospectively freeze one 128-transition inner-cap
trial on the same original four cases/seeds, using this retained 1,024-cap run as
the reference. The lower cap is an already reported Iter173 cost checkpoint, not
an optimized parameter selected from a new sweep. Keep the eight-step horizon,
forward proposal order, evaluator, sampler, metric, ranking, native transport,
full terminal/checkpoint rules and 18,000-transition/120-second/96-action outer
limits unchanged. No replay or retuning of this closed schedule. This is a test
of how total work is distributed, not an increase in compute or source access.

Primary acceptance remains four exact completions with independent admission.
A miss contradicts that candidate qualification; losing the existing completion
is a visible adverse outcome. Record calls, accepted edges, checkpoint attainment
and transition allocation separately. One exposed seed per case supports only a
finite diagnostic; a broader allocation advantage needs new reserved populations.

Alternatives are different prefix ranking, target projection, obstacle guidance
or another planner. Current discarded valid prefixes do not already reach any
failed case's next checkpoint; that does not rule out better future expansion
under another ranking. Unreachable endpoints can also yield useful prefixes.
Test allocation first to distinguish depth within one connection from breadth
across tree requests before changing those other mechanisms.

Resources: the existing CPU/native runtime, four fresh processes, the unchanged
bounded producer/replay envelope and retained evidence. No provider, native drive
or human ceremony. All four cases must qualify before any separately scoped source
comparison. Recoverability from the actual first-fire history, native continuation
and a matched responsive information comparison remain the later mission dependencies.
