## Close the measured question

The released-monitor references, the six finite pulses in Iter139 and the two
nominal continuations in Iter142 produced no useful recovery on this disclosed
case. Nominal continuation delayed collision by 0.75 s; full-route evaluation
rejected it as recovery. This closes the registered case/action comparison.
The tested actions are not exhaustive, so the result is not a proof of physical
unavoidability. Preserve all prior nulls and the Iter141 orchestration failure.
Do not start another pulse, strength or clock search on this case.

## Next fundamental question

Before asking which extra signal improves a decision, establish that an admissible
action can improve the complete outcome, and identify when that opportunity is lost.
A useful information claim requires both an action opportunity and a baseline that
could act on the signal before its deadline. A richer representation alone does not
establish new information or a useful decision.

The next concrete artifact should be a finite case-family protocol and model/control
qualification report built from retained source and scenario inventory:

1. **Qualify the transition and control contract.** Explicitly reconcile controller,
   environment and actor time indexing, units, feasible control bounds and the
   physical scope claimed. Build source-derived deterministic fixtures plus a
   separately implemented state-transition check. If a model change is required,
   version it as a new regime, retain old results and qualify it before any
   comparison. Do not silently repair these historical runs.
2. **Freeze a finite development inventory before outcomes.** Declare eligibility,
   exclusions, source/asset identities, case families, action library and intervention
   times, resources, stopping, missingness and complete-route outcomes. Include
   cases where braking helps, cases where braking harms, and cases where tested
   actions have no demonstrated benefit. Retain failures and all screened cases;
   report the complete inventory so favorable screening cannot become a population
   claim. Use scene independence, not more seeds of this one case.
3. **Establish an action opportunity within that inventory.** Compare a strong
   responsive baseline with the fixed admissible action set using valid branch
   prefixes and live actor feedback. Require a repeatable collision-free complete
   route at useful progress. A successful intervention is a constructive witness
   within the simulator; failure of a finite library means no witness found in that
   library, not impossibility. Privileged state may diagnose an opportunity but
   cannot become undeclared deployed input.
4. **Only then test specified information.** Freeze a selector and signal access,
   compare matched responsive baselines, and include the harmful-intervention cases.
   Separate privileged diagnostic information from available observation. Carry
   compute/communication delay and the behavior when a result arrives late into a
   separately registered deadline experiment. The numerical controller is a research
   instrument; its convergence does not validate a deadline or fallback policy.
5. **Reserve independent evaluation.** Hold new scenes/fault families out from
   selector and threshold choices. Predeclare estimands, scene-level clustering,
   multiplicity and resource bounds. Distinguish opportunity-screened development
   evidence from performance on the original eligible population.

The immediately useful output is a qualified, auditable study design. New cloud
runs should follow that protocol and its executable checks. No broader benchmark,
state-of-the-art or deployment claim has been established by Iter142.
