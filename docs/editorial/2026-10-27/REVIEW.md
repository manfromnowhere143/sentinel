## Design and renderer contract

The design uses semantic subgraphs, short labels, a restrained neutral palette,
a single dark emphasis color, straight routes, explicit proposed-state dashes,
and accessible titles/descriptions. Shapes and words carry meaning without
requiring color discrimination. Every Mermaid block stays below the repository's
1,100-character mobile budget. Four README figures replace the old three;
the text carries the full scientific detail rather than shrinking it into boxes.

Current [Mermaid configuration documentation](https://mermaid.js.org/intro/syntax-reference.html)
and [layout documentation](https://mermaid.ai/open-source/config/layouts.html)
describe newer layout options. GitHub independently chooses its bundled renderer;
its [diagram documentation](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-diagrams)
recommends an `info` diagram to identify that version. These figures use portable
flowchart/subgraph syntax and explicit spacing instead of assuming a particular
new renderer, ELK plugin or external icon pack is available on GitHub. No animation
or layout novelty substitutes for information structure and correct evidence.

All seven changed figures (four README, three architecture) are rendered to SVG
and PNG in both light and dark themes: 28 outputs. The local renderer is Mermaid
CLI 11.4.2 with installed Chrome, at 1,100 CSS pixels and scale 1.5. This records
actual local compatibility, not a claim about GitHub's internal version. The
[render manifest](diagrams/manifest.json) binds all source blocks and artifacts.
Visual review checks label fit, arrows, legibility and light/dark contrast.

The separate endpoint chart plots every admitted node by absolute frame and case.
Its markers distinguish timing exclusions, retained suffixes and unknowns; the
old frame-24 window and required frame-32 checkpoint remain visible. This is a
